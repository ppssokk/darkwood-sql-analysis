# Секреты Темнолесья: анализ игровой экономики

Исследование поведения игроков в онлайн-игре с помощью SQL и PostgreSQL. Проект выполнен в рамках курса Яндекс Практикума по готовому техническому заданию и прошёл ревью. Анализ основан на предоставленных учебных данных.

## Задача

Команда игры планирует привлекать платящих игроков и продвигать покупку эпических предметов. Цель исследования — оценить долю пользователей, покупающих игровую валюту за реальные деньги, изучить внутриигровые покупки и сравнить активность пользователей разных рас персонажей.

## Что сделано

- Рассчитана доля платящих пользователей в игре и в разрезе рас персонажей.
- Изучены количество и распределение стоимости внутриигровых покупок: минимум, максимум, среднее, медиана и стандартное отклонение.
- Найдены покупки с нулевой стоимостью; в последующих расчётах по покупкам они исключены.
- Определены популярные предметы по количеству покупок и доле покупателей.
- Для каждой расы рассчитаны доля покупающих игроков, доля платящих среди них, среднее количество покупок и средние расходы.

## Результаты исследования

По выполненным расчётам и аналитическим комментариям проекта:

- В выборке **22 214 игроков**; из них **3 929**, или около **17,69%**, покупали игровую валюту за реальные деньги. По расам показатель составлял примерно **17,07–19,37%**.
- Зафиксировано **1 307 678 внутриигровых покупок**. Средняя стоимость — около **525,69** единицы игровой валюты, медианная — **74,86**. Существенный разрыв указывает на правостороннюю асимметрию распределения.
- Найдено **907 покупок с нулевой стоимостью** — около **0,069%** от общего количества. Причина нулевых значений по имеющимся данным не установлена.
- Среди покупателей внутриигровых предметов наиболее популярным оказался **Book of Legends**: его приобретали около **88,41%** таких игроков.

Сравнение рас выявило различия в покупательской активности. Результаты описательны: сами по себе они не доказывают причинную связь между расой персонажа и покупками. Для дальнейшего исследования полезно учесть рекламные каналы и изменения игрового баланса.

## Технологии и SQL-приёмы

**PostgreSQL, SQL**: `JOIN`, `LEFT JOIN`, агрегатные и оконные функции, `FILTER`, подзапросы, `COUNT(DISTINCT ...)`, `PERCENTILE_CONT`, `STDDEV`, группировка и сортировка. В одном из запросов фильтр ненулевых покупок находится в условии `LEFT JOIN`, чтобы сохранить игроков без подходящих покупок.

## Запуск

Для выполнения запросов нужен PostgreSQL с учебной схемой `fantasy` и таблицами `users`, `race`, `events`, `items`. Подключитесь к базе в SQL-клиенте, например DBeaver, и запускайте запросы из `analysis.sql` по отдельности. Данные и скрипт создания исходной схемы в репозитории не представлены: без них воспроизвести численные результаты не получится.

`payer` обозначает пользователя, покупавшего игровую валюту за реальные деньги; покупки предметов из таблицы `events` совершаются за внутриигровую валюту. Это разные показатели, поэтому их доли рассчитываются отдельно.
